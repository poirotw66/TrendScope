綜合分析報告：Training, Inference, Agents: Beyond Apps in the AI-Native World

會議概述和核心內容

本次主題演講「Training, Inference, Agents: Beyond Apps in the AI-Native World」由 Linux 基金會 AI 與基礎設施總經理，同時也是 OpenStack 和 OpenInfra 基金會共同創辦人 Mark Collier 於 2025 年 6 月的 AICon Beijing 大會上發表。演講的核心主旨旨在闡述在「AI原生」時代下，人工智慧發展的三大關鍵支柱：訓練 (Training)、推論 (Inference) 和代理 (Agents)，並深入探討開源、基礎設施和社群在塑造這一未來中所扮演的不可或缺角色。

Collier 先生的演講強調，人工智慧的快速崛起已對底層基礎設施提出前所未有的巨大需求，且這一發展趨勢正將計算範式從以應用程式為中心轉變為以模型和代理為中心的「AI原生」模式。他透過回顧 OpenInfra 在中國的十五年發展，以及 Linux 基金會與 OpenInfra 基金會確保「每個計算時代都是開放的」使命，為 AI 原生世界的開放性奠定基礎。簡報最終呼籲透過開放協作和社群力量，共同構建開放、創新且繁榮的 AI 未來。

技術要點和實現細節

本簡報對 AI 原生計算的三大支柱進行了詳盡的技術剖析，並強調了相關的開源工具和架構。

  1. AI 原生計算：

    • 定義： 一種專為模型主導思考和互動的世界所設計的基礎設施。它旨在運行持續學習系統、處理 token 串流和代理工作流程，並優化大規模推論，而非僅僅是靜態程式碼、網頁請求或數據儲存。
    • 軟體自主編寫趨勢： 數據顯示，AI 已經能為微軟、Google 等公司編寫高達 30% 以上的新程式碼，Meta 更預計 AI 將在一年內處理一半的開發者工作，預示著軟體開發模式的根本性變革。

  2. 支柱 ① 訓練 (Training)：

    • 定義： 透過輸入數據調整演算法參數，最終產出可進行預測的模型。訓練方法不斷演進，包括完整預訓練、微調和強化學習等。
    • 技術棧點：
      • 框架/函式庫： PyTorch 是主流，高達 80% 的研究人員使用，並正逐步取代 TensorFlow 成為行業事實標準。
      • 基礎設施黏合層： DeepSpeed、Megatron-LM、Ray 等專案旨在提升大規模訓練的效率和性能。
      • 預訓練模型與數據： DeepSeek-V3、Mistral-7B、RedPajama 等開放權重模型和數據集加速了模型迭代與創新。
      • 模型相容性與匯出： ONNX 和 Hugging Face Transformers 為模型的跨平台部署和互操作性提供支持。
    • 關鍵細節： 開放檢查點和數據集是快速迭代的基石，而開放權重則驅動下游創新。中立的基金會治理模式透過建立信任，促進了生態系統的繁榮。

  3. 支柱 ② 推論 (Inference)：

    • 定義： 載入已訓練模型並對即時請求返回預測結果。其可在邊緣晶片到資料中心的廣泛環境中運行，並高度依賴專用硬體和軟體來優化速度與效率。
    • 重要性： 推論是 AI 產品走向市場的關鍵環節，其工作負載量高達訓練的 50 倍，對商業系統而言，可靠性和效率至關重要。我們正進入一個「自我改進計算」的新飛輪效應時代。
    • 技術棧點：
      • 運行時 / 圖執行： ONNX Runtime 提供可移植的圖執行，TensorRT-LLM 專注於 LLM 推論優化。
      • 分散式引擎： vLLM 已成為事實上的開放生成式 AI 推論平台，能夠在多種模型、硬體和雲端環境中高效運行。llm-d 作為一個新興項目，有望成為「AI 核心」，透過基於 Kubernetes 的大規模分散式推論，實現 Prefill/decode 分離、KV Cache 分布、AI 感知路由器等高級功能。
      • 服務框架： KServe 和 Triton Inference Server 標準化了在 Kubernetes/OpenStack 上部署和服務模型的流程。
      • 優化/快取： LM Cache 等技術用於提升推論效率。
    • 核心概念： 簡報借鑒 Andrej Karpathy 的「軟體 3.0」概念，將 LLM 類比為新一代作業系統，其中推論運行時是核心，代理協議是系統呼叫，代理工作流程是應用程式，工具/技能則是週邊設備。

  4. 支柱 ③ 代理 (Agents)：

    • 定義： 將模型封裝成程式碼，使其能夠呼叫工具、與其他代理或人類對話，並透過開放協議將推論結果轉化為行動。
    • 技術棧點：
      • 編排協議： MCP (Model Communication Protocol) 和 A2A (Agent2Agent Protocol) 是關鍵標準。Google Cloud 將 A2A 移交給 Linux 基金會，標誌著行業巨頭對開放、互通代理生態的共識。
      • 代理框架： LangChain、CrewAI、IDEA、ChatDev 等提供了構建和管理代理的工具。
      • 工具註冊中心 / API： OpenAI Function Calling 和 BentoML Tool Hub 使得代理能夠發現並使用各種工具和外部 API。
      • 記憶體/向量儲存： Chroma、Weaviate、pgvector、Redis-Vector 等支持代理的長期記憶和知識檢索。
    • 核心細節： 軟體焦點從「使用者速度」轉向「代理速度」，並強調「情境工程」(Context Engineering) 比「提示工程」(Prompt Engineering) 更重要，因其涉及向代理提供正確且上下文相關資訊的藝術與科學。小型語言模型 (SLM) 在代理式 AI 中因其效率和適用性被預期將扮演重要角色。
