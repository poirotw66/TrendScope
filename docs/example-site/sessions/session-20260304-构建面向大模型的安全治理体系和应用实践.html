本次演講旨在分享作業幫在資訊安全領域，特別是面對人工智慧（AI）大模型所帶來的雙重機遇與挑戰下，如何創新性地建立其安全防禦與運營體系。核心內容聚焦於以下幾個方面：

  • 背景與挑戰： 闡明隨著AI工具普及，攻擊威脅呈現組織化、產業化，攻擊門檻降低，效率指數級增長。企業內部業務場景多元、員工規模龐大、智能設備接入增加，使得現有三層防禦體系（網絡、傳輸、終端）面臨巨大壓力。主要挑戰在於：1) 海量無效告警佔用大量人力，導致處置效率低下；2) 告警判斷高度依賴安全專家的專業經驗與複雜的場景判斷，難以標準化和自動化。
  • 大模型與治理體系建設： 提出傳統安全運營模式（人工+規則）已無法應對挑戰，引入智能安全運營模式（推理模型+RAG+Agent）勢在必行。詳細解釋了如何克服通用大模型固有的「幻覺」、推理能力不足和知識匱乏等問題，透過RAG技術（結合向量檢索與關鍵詞增強）和智能Agent實現高效、精準、自動化的決策與處置。數據飛輪（PDCA循環）機制被引入，確保系統的可持續優化。
  • 應用實踐與效果收益： 以「威脅流量檢測」為例，展示了新體系如何結合多維上下文進行場景化威脅檢測，提供智能治理建議。成果數據顯示，人工介入量大幅減少（日均從千條降至10條以內），處置時間從小時級縮短至分鐘級，自動化率高達99.99%，告警召回率從89.1%提升至99%+，複雜安全決策準確率提升18.7%。最終，安全防禦體系達到SOMM模型中最高的韌性級（LEVEL 4）。

2. 技術要點和實現細節

作業幫構建的面向大模型的安全治理體系，其技術實現精巧且層次分明，充分體現了對大模型潛力與局限性的深刻理解。

  • 克服大模型固有局限： 演講明確指出了通用大模型在安全領域應用的挑戰，包括幻覺（非事實性回應）、推理邏輯斷層（多步推導難以關聯上下文）、數據過時及特定知識匱乏。為此，其核心技術選型並非簡單地調用大模型，而是採用了協同智能解決方案：

    • 推理模型： 選用Deepseek等長推理大模型作為基座，旨在突破傳統大模型在複雜多步驟邏輯推理方面的瓶頸，確保上下文邏輯關聯的一致性。這表明其對底層模型的選擇是基於對特定任務能力（長推理、邏輯一致性）的考量。
    • 檢索增強生成 (RAG)： 這是解決大模型幻覺與知識匱乏的核心。透過多路召回策略（結合向量檢索與關鍵詞檢索），從內外部知識庫中精準高效地檢索相關信息，並以「最小指令設計」引導大模型依據檢索到的事實生成答案，顯著降低幻覺。
    • 智能Agent： 作為執行層，Agent負責將大模型的決策轉化為實際行動，實現安全運營的閉環。它能自動執行殺毒、發起工單、誤報加白、添加黑名單等操作，極大地提升了自動化水平。

  • 實時報警處置技術架構： 整個流程設計嚴謹，確保從告警產生到處置的快速與精準：

    1. 原始報警數據標準化： 從海量日誌中提取時間、ID、IP、威脅特徵等核心字段。
    2. 完善補充關鍵信息： 動態調用「情報Agent」進行數據增強，區分內外網、定位責任方、識別設備、評估威脅級別，為後續決策提供豐富上下文。
    3. 向量化 (Embedding)： 使用BGE-M3模型將報警信息轉換為高維向量，以便進行語義相似度檢索。BGE-M3模型以其在語義捕捉和泛化能力方面的優勢被選用。
    4. 多路召回： 結合了語義層面的向量檢索和精確匹配的關鍵詞檢索，確保全面且精準地召回歷史相似案例和相關知識。
    5. 大模型處置： 採用「最小指令方式」，即明確指示大模型主要依賴召回的參考內容進行推理，而非自由發揮，進一步限制幻覺。
    6. 多模型交叉驗證： 引入多個基座大模型（如Deepseek, QWEN, GPT-4）對決策結果進行比對。結果一致則採納，出現分歧則進行互驗或轉交人工處理，顯著提升了決策的可靠性。
    7. Agent自動化執行： 將驗證後的決策自動執行，完成安全事件的響應與處置。
    8. 反饋優化數據庫： 人工處理的案例自動入庫，對已有相似案例則優化召回策略和規則邏輯，形成持續學習和改進的循環。

  • 知識庫構建與數據飛輪： 這是系統可持續優化的基石。

    • 知識庫構建： 透過「數據打標 → 文本分塊 → 向量化 → 知識入庫」的標準流程，將歷史報警數據、處置經驗、SOP等結構化與非結構化知識進行整合。其中，「人工審核」作為關鍵環節，確保數據標註的準確性和知識的質量。
    • 數據飛輪（PDCA循環）： 系統的核心運營理念，透過離線與在線數據的持續循環實現自我提升：
      • P (Plan/Predict)： 透過上下文補充和歷史案例追溯，形成對潛在威脅的預判。
      • D (Do/Decide)： 大模型進行智能決策，並透過多模型交叉驗證增強可靠性。
      • C (Check/Control)： Agent執行自動化處置，同時對非確定結果進行人工審核。
      • A (Act/Adjust)： 人工審核的結果和新的處置案例反饋至知識庫，優化數據質量、召回策略和模型邏輯，不斷完善系統。
