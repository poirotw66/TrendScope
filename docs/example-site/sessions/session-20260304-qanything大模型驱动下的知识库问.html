2. 技術要點與實現細節

QAnything 的技術核心在於其精妙設計的 RAG 架構及多項自研技術。

  • RAG 雙階段檢索架構：

    • 文檔處理階段： 支持多種文件格式（PDF, Word, PPT, TXT, Markdown, 網頁連結）上傳。通過 Parser & Splitter（包含 OCR 能力）進行非結構化內容解析、文本切片，隨後利用 Vectorization（Embedding 模型）將文本切片轉換為高維向量，存儲在 Milvus 等向量數據庫中。MySQL 則負責知識庫及文件狀態的管理。
    • 問答流程階段：
      1. Query 理解 (LLM)： 用戶問題首先由大型語言模型進行語義理解。
      2. 1st Retrieval (Embedding)： 基於查詢的 Embedding 向量，從向量數據庫中快速檢索出初步相關的文本片段 (chunks)。
      3. 2nd Retrieval (Rerank)： 這是 QAnything 的核心優勢所在。初步檢索的片段會經過 Rerank 模型進行重排序。簡報通過詳盡的實驗和實例證明，僅靠 Embedding 檢索的「相似」並不等同於實際的「相關」，尤其在數據量龐大時容易出現檢索退化。Cross-Encoder 型的 Rerank 模型能夠更精準地判斷查詢與片段間的真實相關性，從而將最相關的內容推至前列。
      4. Answer Generation (LLM)： 最終，經過 Rerank 精選出的高相關性文本片段，連同用戶原始查詢，一同傳遞給 Reader (LLM) 生成最終答案。
    • 「擴展窗口」機制： 為 LLM 提供更豐富的上下文，當 Embedding Lookup 找到相關句子後，會將這些句子擴展到一個更大的文本窗口，確保 LLM 能夠獲得足夠的上下文來生成準確的答案。

  • 自研 BCEmbedding 與 BCE-reranker 模型：

    • QAnything 在 Embedding 和 Rerank 環節採用了自研的 BCEmbedding 模型和 BCE-reranker 模型。簡報中展示了詳細的 Llamaindex 評測數據，證明這套組合在 hit_rate/mrr 等關鍵指標上顯著優於 OpenAI-ada-2、bge 系列等其他主流開源及閉源模型，尤其在多語種、跨語種及多領域場景下表現卓越（如達到 93.46/77.02 的檢索效果）。
    • BCEmbedding 模型的開源（https://github.com/netease-youdao/BCEmbedding）也體現了其技術自信和社區貢獻。

  • 多模態文檔理解：

    • QAnything 不僅限於文本，還具備處理 PDF, DOCX, PPTX 等文件中的圖片內容的能力。它能對三類圖片進行深度理解：
      • 自然圖片： 提供自然語言描述。
      • 數據類圖片（圖表）： 提取圖元信息（如 X 軸、Y 軸、圖例）、分析數據變化趨勢，甚至支持 CSV 格式數據提取。
      • 流程類圖片： 提供自然語言描述、全流程名稱，並能轉化為 Mermaid 流程圖語言，極大豐富了知識獲取維度。

  • 複雜邏輯解析：

    • 為應對複雜查詢，QAnything 打破傳統「單步檢索」模式，引入「問題分層拆解 + 多輪推理」機制。系統能夠將一個複雜問題自動分解為多個子問題，逐步進行檢索與推理，最終綜合生成詳細答案，提升了對複雜業務場景的適應性。

  • 部署與性能優化：

    • 支持全離線私有化部署，兼容本地 LLM (vllm) 和本地 Embedding + Rerank + 解析，實現完全斷網使用。
    • 利用 Docker 與 Docker Compose 實現「一鍵部署」，極大簡化了部署流程，降低了技術門檻。
    • 從 FAISS 到 Milvus 再到 Zilliz 的向量數據庫演進，顯示了對性能和用戶管理能力的持續追求。
