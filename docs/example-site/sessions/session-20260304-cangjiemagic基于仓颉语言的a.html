2.1 CangjieMagic 框架層面

  • 分層架構設計（Page 11）：框架分為「編程界面」和「運行底座」兩層。
    • 編程界面：提供 Agent DSL，簡化單 Agent 編寫，支援 Agent 定義、提示詞模式、數據自動轉換、對話作用域，並統一接入工具和支援多 Agent 協同。
    • 運行底座：包含規劃模組（規劃方法庫、智選）、記憶模組（RAG、會話、個性化記憶）、工具模組（MCP 協議、工具執行與智選）、Agent 協同模組（線性、主從、自由協同）和單 Agent 執行模組（提示詞組裝、結構數據轉換）。運行底座能連接端側與雲側 LLM。
  • Agent DSL 極簡高效開發（Page 12, 20）：
    • 透過 @agent 註解一鍵配置模型、規劃器和工具，如 deepseek:deepseek-chat 和 plan-react。
    • @prompt 註解支援預置模式和「完形填空」式提示詞引導，實現程式碼與自然語言的無縫融合。
    • 多 Agent 協同 DSL：巧妙利用倉頡語言的操作符重載特性，提供直觀的語法糖來表達不同協同模式：
      • 線性協同 (ag1 |> ag2 |> ag3)：透過流操作符重載，實現 Agent 依序執行並傳遞消息。
      • 主從協同 (ag1 <= [ag2, ag3])：透過關係操作符重載，主 Agent 選擇成員 Agent 進行點對點溝通。
      • 自由協同 (ag1 | ag2 | ag3)：透過邏輯操作符重載，Agent 自由通信，消息廣播，由 LLM 決定任務分配。
  • 統一接入工具（Page 13）：
    • 框架提供標準化、配置化的工具編寫方式，透過 MCP (Magic Common Protocol) 實現統一接入。
    • Agent 能夠在運行時智能選用工具並組裝，擴展其獲取最新知識、感知環境、實施操作的能力。工具類型包括開發者自定義函數、其他 Agent、檢索服務（RAG）和外部 MCP 工具。
  • 智能規劃策略（Page 14）：
    • 支援預置的規劃方法（Naive, React, Plan-react）。
    • 允許開發者透過 DSL 開發自定義規劃方法，如 while ($incomplete) { think |> act }，將規劃過程分解為原子操作（Think, Act），提供高度靈活性。
  • 長短期記憶機制（Page 15）：
    • 短期記憶：透過 @conversation 註解自動維護對話歷史，支援多輪交互，加速相似任務執行。
    • 長期記憶：透過 @agent[memory: true] 啟用，沿用 RAG 方法，將問答過程保存至向量數據庫，實現跨會話的知識共享和語義檢索。
  • 高度模組化與可擴展性（Page 16）：CangjieMagic 框架將模型 (@chatModel)、執行器 (@executor) 和檢索器 (@retriever) 等核心組件高度模組化，開發者可獨立定義和替換，實現低耦合和強大的自定義能力。
