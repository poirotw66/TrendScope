# GenAI 應用時代，開發思想如何變革？— AICon Beijing 202506 主題演講綜合分析報告

## 執行摘要

本報告根據莫欣先生在 2025 年 AICon Beijing 大會上的主題演講《GenAI 應用時代，開發思想如何變革？》的 PPT 內容，提供一份全方位的綜合分析。演講核心闡述了在生成式人工智慧（GenAI）浪潮下，軟體開發範式、技術棧以及開發者分工協作關係所面臨的深遠變革。莫欣先生透過其負責的 Agently.tech 框架的實例，深入剖析了 `Function Calling`、智能輸出控制以及「**IN CODE AT RUNTIME**」等關鍵概念，並強調了開發框架在適應新生產關係中的不可或缺性。

本報告將從會議概述、技術要點、商業價值、創新亮點和趨勢洞察五個方面，為技術、商業和趨勢關注者提供全面而深入的視角。

## 1. 會議概述和核心內容

本次主題演講由北京智體紀元科技有限公司創始人莫欣先生，於 2025 年的 AICon 全球人工智能開發與應用大會上發表。會議背景設定在 GenAI 應用時代，旨在探討其對軟體開發思維模式的根本性衝擊與轉變。

演講的核心內容圍繞五個議題展開：
1.  **空函數的魔力：** 透過 Agently 框架展示，即使沒有實作代碼的函數，也能在 GenAI 賦能下智能運行，完成複雜任務（如搜索定義、生成 SQL）。這揭示了 GenAI 將模糊輸入轉化為結構化輸出、進而執行複雜邏輯的潛力。
2.  **智能輸出控制的重要性：** 闡明 `Function Calling` 及其他智能輸出控制機制是實現「符合業務需要的智能」的關鍵。強調模型僅提供基礎智能，真正的業務價值來自於對模型行為的精確控制和「智能處理過程的白盒化」。
3.  **GenAI 對傳統架構與分工的衝擊：** GenAI 模糊了傳統三層架構中表示層、應用層和數據層的界限，特別是在處理「模糊輸入」時。這對產品經理和工程師的職能、協作關係及業務邊界提出了重新定義的需求。
4.  **開發者角色的轉變：** 儘管 GenAI 擴展了非技術人員的行動力，但提供可持續的「線上服務」仍需開發者關注傳統的系統工程問題。開發者需將重心從底層細節轉向更高層次的「業務流程梳理、業務架構設計和數據結構設計」，並接受「IN CODE AT RUNTIME」這一新範式。
5.  **開發框架的關鍵作用：** 好的 GenAI 開發框架並非過度封裝，而是簡化底層複雜性，讓開發者專注於核心業務邏輯，提供「文思泉涌的開發心流體驗」。Agently.tech 作為範例，展示了框架如何融合自然語言與代碼、控制輸出穩定性、自由切換模型和工具、並將可視化工作流順暢遷移至代碼。

總而言之，演講的核心思想是：GenAI 時代的開發不再是靜態代碼的堆砌，而是擁抱「**IN CODE AT RUNTIME**」這一動態、智能處理的範式，要求開發者轉變思維，掌握智能輸出控制，並善用開發框架來應對複雜性。

## 2. 技術要點和實現細節

演講深入探討了 GenAI 應用開發的多項技術要點，並透過 Agently.tech 框架揭示了其實現細節。

### 2.1 「空函數」與 `@agent.auto_func` 的魔力

*   **技術要點：** 演講以兩個「空函數」範例（`check_definition_from_question` 和 `write_SQL_for_different_DB`）震撼開場。這些函數儘管缺乏傳統意義上的實作邏輯，卻能根據函數簽名、註釋（docstring）和預期輸出結構，透過 GenAI 在運行時（IN CODE AT RUNTIME）自動執行複雜任務。
*   **實現細節：** 莫欣先生揭示了 `@agent.auto_func` 裝飾器的底層機制。它並非魔法，而是 Agently 框架基於 **Agent (代理)** 概念的實現。當函數被 `@agent.auto_func` 裝飾時，Agently 會：
    1.  **創建代理：** 為該函數實例化一個 AI 代理。
    2.  **模型集成：** 配置代理使用特定的基礎模型（如 DeepSeek）及其 API 密鑰。
    3.  **工具賦能：** 為代理提供一系列外部工具（Tools），例如 `search` 用於互聯網搜索，`browse` 用於瀏覽網頁，或自定義的數據庫查詢工具。
    4.  **智能編排：** 代理在運行時根據函數的註釋、輸入參數和預期輸出，結合其內置的模型能力（理解、判斷、規劃）和可用工具，動態地生成並執行一系列行動計劃，最終返回符合預期格式的結果。這整個過程是在代碼運行時動態發生的。

### 2.2 智能輸出控制 (Intelligent Output Control)

*   **技術要點：** 這是演講的核心技術觀點之一。模型本身提供的「基礎智能」是通用的，而「符合業務需要的智能」則需要精確的控制和編排。智能輸出控制旨在解決 GenAI 輸出不穩定、不可控的問題，使其能被後續業務流程可靠地消費。
*   **實現細節：**
    *   **模型驅動的智能處理過程：** 強調真正的智能來自於圍繞模型設計的動態處理流程，而非僅僅依賴模型本身。
    *   **Function Calling 的再定義：** 演講指出，`Function Calling` 不僅是模型的一個接口能力，其核心在於「**構建上述處理過程**」。開發者即使面對不原生支援 `Function Calling` 的模型，也能透過自主編排和協調，實現類似甚至更複雜的工具調用效果。
    *   **智能處理過程白盒化：** 這是一個關鍵的理念。將 AI 的決策和執行過程透明化，讓開發者能夠清晰理解模型如何判斷、如何調用工具、如何處理信息，從而可以根據業務實際情況，靈活調整和優化處理流程。
    *   **七大挑戰：** 演講明確指出了自主構建智能處理過程需要解決的七個問題，例如將模型結果作為分支判斷條件、調用外部模塊、識別用戶意圖、編排複雜過程等，這些都是智能輸出控制的具體技術細節。

### 2.3 GenAI 應用三大關鍵要素

*   **模型 (Model)：** 提供基礎智能（理解、判斷、規劃、表達），是底層的 ChatBot 能力。
*   **數據 (Data)：** 進行知識補充（RAG、微調），形成客服、知識庫機器人。
*   **控制 (Control)：** **最被強調的要素**。定義行為方法（行動規劃/編排、工具/模塊調用、運行時處理、數據持久化），是實現智能個人助理、營銷流水線等高級應用的關鍵。Agently 框架正是圍繞「控制」這一核心要素而設計。

### 2.4 「IN CODE AT RUNTIME」新範式

*   **技術要點：** 這是演講中反覆強調的核心概念。它代表了 GenAI 時代軟體開發最根本的範式轉變。傳統軟體是將邏輯「編寫進代碼」並靜態運行，而「IN CODE AT RUNTIME」意味著 AI 的智能邏輯在代碼運行時被動態生成、調用和執行。
*   **實現細節：**
    *   它不是簡單的 AI 編碼輔助，而是讓代碼本身具備了動態適應和決策的能力。
    *   工程師接受此範式後，將能實現更複雜的流程編排（級聯遍歷、遞歸、動態拼裝）、更全面的信息系統觀（從用戶交互中發現信息並協同模塊完成任務）、以及將 GenAI 能力無縫融入業務流程。
    *   Agently 框架通過 `@agent.auto_func` 讓開發者能夠以函數簽名和註釋的形式，直接在代碼中定義 AI 的動態行為，是「IN CODE AT RUNTIME」的具體實現。

### 2.5 開發框架的技術賦能 (Agently.tech 為例)

Agently 框架旨在提供「文思泉涌的開發心流體驗」，其技術細節體現在：
*   **自然語言與代碼融合：** 允許開發者在函數註釋中直接使用自然語言描述需求，與代碼規範結合，極大簡化 AI 邏輯定義。
*   **Prompt 靈活性與輸出穩定性：** 透過 `agent.input().instruct().output().start()` 等鏈式調用，在保持 Prompt 表意靈活性的同時，增強對模型輸出格式的嚴格控制和解析，解決了 GenAI 輸出不確定性的痛點。
*   **模型自由切換與工具調用：** 支援多種底層模型自由切換，且不依賴模型原生接口即可調用外部工具，並支持多代理協作（MCP）。
*   **可視化工作流遷移：** 提供流暢的編程體驗，使可視化設計的工作流可以無縫轉化為可維護、可調試的代碼，兼顧了設計效率和工程化需求。

## 3. 商業價值和應用場景

GenAI 帶來的開發思想變革不僅僅是技術層面的演進，更對商業模式和應用創造產生了深遠的價值。

### 3.1 商業價值

1.  **提升開發效率與質量：**
    *   **簡化複雜性：** 開發框架（如 Agently）抽象了模型接口調用、數據轉換、輸出控制等底層繁瑣細節，讓開發者專注於業務邏輯和 AI 能力的應用，大幅提升開發效率。
    *   **加速創新：** 「空函數」和「IN CODE AT RUNETIME」範式使得業務需求的快速原型驗證和迭代成為可能，加速了新 AI 應用從概念到落地的週期。
    *   **提高可靠性：** 智能輸出控制和「白盒化」處理過程，確保 AI 輸出的穩定性、準確性和可控性，對於需要高可靠性的商業應用至關重要，降低了潛在的業務風險。

2.  **拓寬應用邊界與創新產品形態：**
    *   **彌合人機交互鴻溝：** GenAI 能夠直接理解用戶的「模糊表達」，並將其轉化為結構化指令和數據訪問方案，使得用戶界面設計更加自然、智能化，提升用戶體驗。
    *   **賦能非技術人員：** 雖然不能完全取代開發者，但 GenAI 確實極大擴展了非技術人員的行動力，使他們能夠完成信息處理、內容生成等單次任務，為企業內部協作和個人生產力帶來提升。
    *   **實現高級智能自動化：** 從簡單的 ChatBot 到具備行動規劃、工具調用和運行時決策能力的智能個人助理、智能營銷流水線、智能設備控制等，GenAI 能夠實現過去難以想像的複雜自動化和智能化應用。

3.  **優化資源配置與成本效益：**
    *   **人效提升：** 由於開發者可以將精力集中於更高層次的業務架構和數據設計，團隊可以更高效地利用人力資源，減少重複勞動。
    *   **靈活應對市場變化：** 「智能處理過程白盒化」使得 AI 應用的行為邏輯可以根據業務實際情況靈活調整，快速響應市場變化，提升企業的應變能力。

### 3.2 應用場景

1.  **智能助手與客服：**
    *   **智能個人助理：** 能夠理解用戶模糊指令，協調多個系統和工具（如日曆、郵箱、CRM），自動規劃和執行任務（如「幫我查一下明天的會議並預約午餐」），如 Agently 演示的自動發送會議提醒郵件。
    *   **知識庫機器人 / 客服機器人：** 結合 RAG 技術，從海量內部或外部知識中檢索信息，並以自然語言提供精準、個性化的回答，大幅提升客戶服務效率和滿意度。

2.  **數據分析與業務自動化：**
    *   **智能數據分析與報告生成：** 如演講中展示的自動生成複雜 SQL 查詢，用戶僅需提供自然語言問題和數據庫元數據，即可獲得可執行的查詢語句，極大降低了數據分析的門檻。
    *   **智能營銷流水線：** 自動生成營銷文案、圖片、短視頻，並根據用戶反饋調整策略，實現從內容創作到投放、分析的全流程自動化。
    *   **智能合同審閱與法務助手：** 理解合同條款，識別潛在風險，或根據需求自動生成標準合同範本。

3.  **內容創作與媒體：**
    *   **長文寫作與新聞搜索匯總：** 自動收集、整理多源信息，並生成符合特定風格和格式的長篇文章或新聞摘要。
    *   **多模態內容生成：** 自動生成短視頻、播客音頻、圖片等，如非技術人員快速創建網頁界面。

4.  **智能設備與物聯網控制：**
    *   **智能設備控制：** 透過自然語言指令控制智能家居設備，甚至實現更複雜的聯動場景（如「我快到家了，幫我提前打開空調並播放背景音樂」）。
    *   **具身智能 (Embodied AI)：** 未來 GenAI 將與物理世界深度結合，實現更智能的機器人操作和自主決策。

這些應用場景的實現，都離不開對模型輸出和行為的精準「控制」，以及「IN CODE AT RUNTIME」的動態決策能力。

## 4. 創新亮點和技術突破

本次演講不僅僅是技術的羅列，更在思想和實踐層面提出了多個創新亮點和技術突破。

1.  **「IN CODE AT RUNTIME」的範式創新：**
    *   **突破點：** 這是本次演講最核心的創新理念。它超越了傳統的「AI 輔助編碼」或「AI 作為獨立工具」的思維，將 AI 的智能內核深度融入到軟體運行時的決策和行為中。傳統代碼是靜態邏輯的定義，而「IN CODE AT RUNTIME」讓代碼在運行時具備了動態生成、編排和執行智能邏輯的能力。這模糊了設計時與運行時的界限，使得軟體系統更具適應性和柔韌性。
    *   **具體呈現：** Agently 的 `@agent.auto_func` 就是這一理念的絕佳體現，它讓一個「空函數」能夠在運行時基於自然語言的意圖和預期輸出，自動選擇工具、規劃步驟並完成任務。

2.  **智能輸出控制與「白盒化」的實用突破：**
