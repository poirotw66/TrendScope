### 二、 技術要點和實現細節

京東零售在大模型推理優化方面展現了從底層硬體到上層應用的全棧技術棧，其核心技術要點和實現細節體現了對效率、時延和吞吐量的極致追求。

**2.1 大模型應用面臨的技術挑戰**
演講精準指出了大模型應用中的三大核心技術挑戰：
*   **效能、效果與效率的平衡：** 巨大的模型參數量導致高昂的計算資源消耗和記憶體壓力。例如，DeepSeekR1-671B（FP8）模型需要 671GB 記憶體，遠超單張 H20 GPU 的 96GB 顯存，這要求極致的模型輕量化和高性能優化。
*   **硬體瓶頸：** 記憶體容量和訪存頻寬成為「記憶體牆」瓶頸，尤其在自回歸解碼的 Prefill（計算密集）和 Decode（記憶體密集）階段，計算特性差異導致算力利用率低，而 KV Cache 更是顯存佔用飆升的罪魁禍首。
*   **服務場景高度多樣化：** 用戶請求負載波動大、輸入/輸出長度動態變化、不同的服務等級目標（SLO）和請求優先級，以及多模態支持、異構硬體部署等，都對推理系統的穩定性、彈性和調度能力提出了嚴苛要求。

**2.2 京東的核心優化實踐與技術實現**

針對上述挑戰，京東構建了一套集分佈式、異步化、軟硬體協同於一體的綜合推理優化體系：

1.  **分離式架構（Separated Architecture）：**
    *   **設計理念：** 深度解耦傳統單體模式，將模型結構、計算階段和存儲資源分離，實現模型並行（TP/PP/EP/DP）、計算階段（PD/EPD）分離和 KV Cache 存儲池化。
    *   **多維混合並行：** 結合了張量並行（TP）、流水線並行（PP）、專家並行（EP）、數據並行（DP）的優勢。尤其針對 MoE 模型，通過 EP/TP/DP 的混合並行，將總參數 6710 億、單次激活 370 億的模型高效分佈到多個 GPU 上，有效降低單設備記憶體壓力，提高計算並行度。
    *   **PD/EPD 分離：** 針對 Prefill 和 Decode 階段不同的資源需求（Prefill 計算密集，Decode 記憶體密集），將兩者資源隔離部署，獨立處理與優化，有效降低了 TTFT（首字時延）和 TBT（字間時延），提升系統吞吐。對於多模態大模型（VLM），進一步引入 EPD 分離，實現圖像預處理、編碼與文本 Tokenizer 的異步並行。
    *   **KV Cache 傳輸優化：** 在 PD 分離場景下，優化了 KV Cache 的傳輸通道（從 Device 直推到 Offload DRAM），並實現了分塊傳輸（Layer-wise 與按需合併），減少了傳輸時延。

2.  **KV Cache Pool：**
    *   **問題：** KV Cache 隨序列長度線性增長，佔用大量顯存。
    *   **解決方案：** 將 KV Cache Offload 到 DRAM/SSD 擴展 HBM 空間，並將不同實例的多級 KV Cache 存儲（HBM/DRAM/SSD）做全局共享管理，組建「KV Cache Pool」，用於全局 Prefix Cache 和 PD KV Cache 傳輸。這從根本上解決了 KV Cache 導致的「記憶體牆」問題。

3.  **多級負載均衡：**
    *   **問題：** 傳統 RoundRobin 無法感知 Instance 真實負載（特別是 KV Cache 佔用），導致負載不均和性能瓶頸。
    *   **解決方案：** 引入全局調度器，實現 Prefix Cache Aware 和 KV Cache Aware 的智能調度。同時，針對 DP 和 EP 並行場景，分別設計了 DPLB (Data Parallel Load Balancing) 和 EPLB (Expert Parallel Load Balancing)，有效平衡了各工作負載，避免熱點問題，提升了整體時延。

4.  **多層流水線 Overlap：**
    *   **問題：** CPU 調度與 NPU/GPU 計算串行、單流計算與通信交替執行、計算與數據搬運串行等，導致資源利用率低下，產生大量「bubble」。
    *   **解決方案：**
        *   **CPU 與 NPU 計算異步流水線：** 採用 fake token 技術，提前執行下一迭代的 CPU 調度，與當前迭代的 NPU forward 計算重疊。
        *   **NPU 計算與通信異步流水線：** 使用雙流（兩個 micro batch），將前一個 batch 的通信與當前 batch 的計算重疊。
        *   **算子內部并行：** 利用 NPU Cube 計算單元、Vector 計算單元、訪存流水并行。
        *   **投機推理優化：** 在 DeepSeek MTP 投機推理中，通過提前準備下一迭代的 Input，減少 Draft/Target 模型交互中的等待時間。
        *   **PD 分離通信與計算 Overlap：** LayerWise 異步傳輸 KV Cache，與當前迭代的 forward step 重疊，顯著降低長序列傳輸耗時。

5.  **模型壓縮與高性能算子：**
    *   簡報提及了 LLM 加速技術中的模型壓縮（如 AWQ/Smooth Quant, INT4/INT8/FP8 量化）和高性能算子（如 FlashAttention, FlashInfer, Kernel Launch, CudaGraph），這些是優化基礎性能的關鍵。特別是 DeepSeek 模型在 MLA（多頭潛在注意力）上的創新，實現推理顯存降低 80%以上。

綜合來看，京東的優化實踐是從宏觀的系統架構設計到微觀的算子級優化，再到硬體層面的深度協同，構成了一個全面的、多層次的優化體系。

### 四、 創新亮點和技術突破

京東零售在大模型推理優化方面的創新和突破是其核心競爭力之一，主要體現在以下幾個方面：

1.  **分佈式推理架構的深度解耦與創新：**
    *   **分離式架構 (Separated Architecture)：** 這是一個領先業界的架構設計。京東不僅採用了業界通用的 TP/PP/DP 等並行策略，更進一步將模型結構、計算階段（Prefill/Decode, Encoder/Prefill/Decode）和存儲資源深度解耦。這種分離允許對不同階段的資源需求進行精準匹配和獨立優化，突破了傳統單體部署的限制，為彈性、高效、可擴展的分布式推理系統奠定了基礎。
    *   **PD/EPD 分離：** 針對 Prefill/Decode 和多模態 Encoder-Prefill-Decode 階段不同的計算/記憶體特性，進行資源隔離部署，並為其定制優化方案，是解決連續批處理中資源干擾、提升效率的巧妙創新。

2.  **KV Cache 管理的突破性解決方案：**
    *   **KV Cache Pool：** 針對 KV Cache 導致的「記憶體牆」瓶頸，京東提出的將 KV Cache Offload 到 DRAM/SSD，並將多級存儲全局共享管理的「KV Cache Pool」是一個實用且高效的解決方案。它不僅有效擴展了可用記憶體空間，更實現了 Prefix Cache 的高效復用，極大地提升了吞吐量和降低了成本。

3.  **智能、精細化的多級負載均衡：**
    *   **Context-Aware 調度：** 引入全局調度器，實現 Prefix Cache Aware 和 KV Cache Aware 的智能調度，這超越了簡單的 RoundRobin 策略，能夠實時感知 Instance 的真實負載狀態，從而做出更優的資源分配決策。
    *   **專用並行負載均衡 (DPLB/EPLB)：** 針對數據並行 (DP) 和專家並行 (EP) 特性，設計專門的負載均衡策略，有效解決了並行計算中的負載差異和熱點問題，確保了整體系統的高效運行。

4.  **多層次、深度重疊的流水線優化：**
    *   **CPU-NPU 異步流水線與 Fake Token 技術：** 通過使用 Fake Token 提前執行 CPU 調度，實現 CPU 與 NPU 計算的異步並行，有效減少了串行等待時間。
    *   **計算與通信雙流異步：** 利用多個 Micro Batch 實現計算與通信的深度重疊，打破了傳統串行執行的限制，最大化了硬體資源利用率。
    *   **投機推理的精細化優化：** 在 DeepSeek MTP 等投機解碼技術的基礎上，京東通過前瞻性的 Input 準備，減少了 Draft Model 和 Target Model 之間交互的 bubble，進一步榨取了投機解碼的潛力。

5.  **軟硬體深度協同的戰略佈局：**
    *   從簡報中可以看出，京東不僅在軟體層面進行了大量創新，還積極支持國產晶片 NPU 推理，並構建了如 CloudMatrix384 這樣的超節點集群，具備全對等互聯和光通信技術。這種軟硬體深度協同的策略，旨在打開算力存儲與通信天花板，實現單集群如「一體機」的效果，是未來 AI 基礎設施發展的重要方向。

這些創新亮點共同構成了京東在大模型推理優化領域的技術護城河，使其能夠在激烈的市場競爭中保持領先地位，並持續為業務創造價值。
