### 1. 會議概述和核心內容

本次 AiCon 主題演講由同程旅行的工程效能架構師楊方偉主講，深入探討了如何利用 `Coding Agent` 技術顯著提昇研發效率，並將其應用範圍從單點實踐擴展至全面的研發流程改進。簡報分為四大核心章節：

1.  **從程式碼補全到對話式程式設計：** 追溯 AI 在程式設計領域的演進，從最初的基礎輔助功能（如程式碼補全）發展到具備更強上下文理解和對話互動能力的 `Agent` 形態。
2.  **內部實踐：Coding Agent 在我們團隊的落地：** 詳細介紹同程旅行內部引入 `Coding Agent` 的契機、導入過程、所面臨的挑戰及應對策略，並展示了多供應商整合的具體實踐與量化成效。
3.  **從點到面：建構可持續的研發智能化：** 聚焦如何將 `Coding Agent` 的應用從單一工具或場景推廣至整個研發生命週期，透過核心平台 MCP (My Code Pilot/Matrix Code Pilot) 實現數據與工具的深度結合，以及流程的重塑。
4.  **總結與展望：** 提煉 `Coding Agent` 成功的關鍵要素，並對 AI 在未來軟體開發中的角色演進進行趨勢性預測。

核心思想是，AI 不僅是開發者的「工具」，更應成為能夠「驅動」整個研發流程的「代理人」，透過智能化手段實現從需求分析到部署運維全鏈路的效率與品質雙重飛躍。

### 2. 技術要點和實現細節

#### 2.1 AI 在程式設計中的演進與 Agent 架構

*   **從程式碼補全到對話式程式設計：** 演講指出，早期的 AI 輔助開發主要集中在程式碼補全、註釋生成、單元測試生成等點狀功能。隨著大型語言模型 (LLM) 的發展，AI 已能從「無上下文」逐步理解「單文件」、「多文件」乃至「整個專案」的複雜上下文，互動方式也從「固定提示」轉變為「自然語言對話/指令」，最終目標是實現「任務驅動的自主執行」。
*   **Agent 架構核心驅動：** `Coding Agent` 不再僅是提供建議的基礎工具，而是透過 `Agent` 架構，讓 AI 具備感知、決策、規劃並執行複雜編碼任務的能力。儘管當前模型在複雜上下文理解和擺脫對技巧性 Prompt 依賴方面仍有挑戰，但 Agent 架構是實現「自動化開發者」的關鍵。

#### 2.2 多模型與多工具整合策略

*   **異構資源整合：** 同程旅行採取了多供應商接入策略，整合了多種前端 AI 程式設計工具 (如 Comate, GitHub Copilot, Cursor, Cline) 和底層大型語言模型 (如 DeepSeek, 文心一言/Ernie Bot, OpenAI 的 GPT 系列, Claude 系列)。這種策略旨在利用不同模型和工具的特長，提供更靈活、高效且具彈性的 AI 輔助能力。
*   **「高品質輸出公式」：** 實現 AI 高品質輸出的核心要素被歸結為：模型能力 + 明確的指令 + 清晰的文件 + 規範的示例程式碼。這強調了除了模型自身能力外，優質的輸入和上下文對於 AI 的表現至關重要。

#### 2.3 核心平台：MCP (My Code Pilot / Matrix Code Pilot)

*   **「會思考的『萬能膠』」：** MCP 被定位為一個能夠連接、管理和協調各種 AI 工具、數據和研發流程的核心平台。它負責補充資訊並進行更精確的加工，是將 LLM 能力與實際研發場景深度融合的關鍵。
*   **部署與風險控制：** 實現 MCP 需建構 SSE/Streamable HTTP 託管服務、STDIO/API 到 SSE/Streamable HTTP 的轉換以及 MCP Gateway。在風險控制方面，實施了帳號級控制、網路層控制以及 Agent 操作確認機制，確保 AI 協同的安全性與可控性。
*   **角色轉變的技術基礎：** MCP 使得工程師能夠從過去的「翻譯官」和「流程設計師」轉變為「能力定義者」，透過打造獨立的「工具」（如查詢訂單 API、發送郵件 API）並提供說明書，讓 AI 作為「執行官」來理解命令、規劃步驟、組裝工具並調用。

#### 2.4 AI 賦能研發流程的具體實踐

簡報展示了 MCP 結合 LLM 在多個研發環節的應用：

*   **程式碼生成與優化：** 初期工作涵蓋逐行補全、方法程式碼塊補全，以及程式碼優化和單元測試生成。多供應商接入的實施步驟為：生成骨架 → 填充方法 → 人工優化 → 生成單測 → 自動測試。
*   **測試用例自動生成：** 基於 MCP 和明確的 `rules`，AI 可以自動生成符合規範的測試用例，並透過其他 MCP 工具進行校驗。
*   **CI/CD 智能輔助與異常分析：** 在 CI/CD 流程中，AI 能夠診斷 Docker 建構錯誤等異常，提供原因和解決方案。更重要的是，它建立了一個閉環學習系統：AI 解決方案會被保存、文檔化並加入特徵值庫，持續優化故障診斷能力。
*   **智能化程式碼審查與靜態分析：**
    *   **程式碼審查：** AI (如 DeepSeek-R1 和 ChatGPT) 可提供細緻的程式碼改進建議，從邏輯處理、安全性（如 SQL 防注入）、程式碼風格到返回值處理。
    *   **靜態程式碼分析與缺陷分析：** 結合 `commits diff`、調用鏈路分析數據和 IDE 的 codebase 資訊，MCP 能夠發現潛在的運行時問題 (如空指針檢查缺失) 和規範缺陷 (如異常處理不當)，並提供改進建議。
